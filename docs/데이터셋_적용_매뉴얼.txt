============================================================
 데이터셋 ZIP 다운로드 → 시드 적용 매뉴얼
============================================================
이 문서는 "📤 데이터셋 내보내기"로 받은 ZIP 파일을, 다른 PC/새 설치본에
데이터셋(시드)으로 적용하는 방법을 설명합니다. 코딩 지식 없이 따라 할 수
있도록 단계별로 정리했습니다.


------------------------------------------------------------
 0. 한눈에 보기 (요약)
------------------------------------------------------------
  1) 웹 화면 "🗂️ 데이터 현황" 탭에서 [📤 데이터셋 내보내기] 클릭 → ZIP 다운로드
  2) 받은 ZIP 파일 이름을  dataset_seed.zip  으로 바꾸기
  3) 그 파일을 프로젝트의  data/  폴더에 넣기  (기존 파일 있으면 덮어쓰기)
  4) 서버 재시작  →  기동 시 자동 복원 + 누락분 증분 수집
  끝.


------------------------------------------------------------
 1. ZIP 내보내기 (데이터 export)
------------------------------------------------------------
- 서버 실행 상태에서 웹 화면을 엽니다.
- 상단 "🗂️ 데이터 현황" 탭에 있는 초록색 [📤 데이터셋 내보내기] 버튼을 누릅니다.
- 잠시(수 초~2분) 후 다음 형식의 ZIP이 다운로드됩니다.

      btc-grid-dataset_YYYY-MM-DD.zip
      예) btc-grid-dataset_2026-06-28.zip

- ZIP 안에는 다음이 들어 있습니다.
      daily_btc.csv            BTC/KRW 일봉 전체
      daily_usdt.csv           USDT/KRW 일봉 전체
      minute_KRW-BTC_5m.csv    BTC 5분봉 (수집분)
      minute_KRW-USDT_5m.csv   USDT 5분봉 (수집분)
      minute_*_1m.csv          1분봉 (수집된 경우)
      fx_usdkrw.csv            원/달러 환율
      kimchi_premium.csv       김치프리미엄
      monthly_labels.csv       BTC 월별 지도학습 라벨셋
      monthly_labels_usdt.csv  USDT 월별 라벨셋
      meta.json                스키마 / 행수 / 생성시각

  ※ 이 ZIP은 그대로 ML 실험 환경에 업로드해도 되고(분석용),
    아래 2~3단계처럼 다른 설치본의 "시드"로도 쓸 수 있습니다(운영용).


------------------------------------------------------------
 2. 파일 이름 바꾸기
------------------------------------------------------------
- 다운로드한 ZIP의 이름을 정확히 아래로 바꿉니다.

      dataset_seed.zip

- 압축을 풀 필요는 없습니다. ZIP 파일 그대로 둡니다.
  (서버가 기동할 때 ZIP 내부를 직접 읽어 복원합니다.)


------------------------------------------------------------
 3. data 폴더에 넣기
------------------------------------------------------------
- 이름을 바꾼  dataset_seed.zip  을 프로젝트의  data/  폴더에 복사합니다.

      <프로젝트폴더>/data/dataset_seed.zip

- 같은 이름의 파일이 이미 있으면 덮어씁니다.
- 만약 같은 폴더에  dataset_seed.zip.imported  라는 파일이 보이면,
  그건 "이전에 한 번 처리 완료됨" 표시입니다. 새 ZIP을 넣으면 서버가
  날짜를 비교해 더 최신일 때 자동 적용하므로 별도 조치는 필요 없습니다.


------------------------------------------------------------
 4. 서버 재시작
------------------------------------------------------------
- 서버를 껐다가 다시 켭니다.
      Windows:  start.bat  실행
      직접 실행:  python api_server.py

- 기동 로그(검은 콘솔 창)에 복원 메시지가 보이면 성공입니다.
  복원이 끝나면 서버는 dataset_seed.zip 을
  dataset_seed.zip.imported 로 자동 변경합니다(중복 복원 방지).

- 이후 서버는 시드 마지막 시점 이후의 누락분만 자동으로 증분 수집합니다.
  (수 시간 걸리던 분봉 처음부터 받기 과정이 생략됩니다.)


------------------------------------------------------------
 5. 자주 묻는 상황
------------------------------------------------------------
Q. 다시 적용하고 싶은데 복원이 안 돼요.
   → 새 ZIP을  dataset_seed.zip  으로 넣고 서버를 재시작하세요.
     서버는 시드의 일봉 마지막 날짜가 현재 데이터보다 "더 최신"일 때만
     복원합니다(갱신 시드 자동 적용). 시드가 더 오래됐거나 같으면 건너뛰고
     자동으로 .imported 처리됩니다 — 이 경우 복원할 것이 없다는 뜻입니다.

Q. 압축을 풀어서 CSV들을 직접 넣어야 하나요?
   → 아니요. ZIP 그대로  data/dataset_seed.zip  에 두면 됩니다.

Q. 기존 데이터가 사라지나요?
   → 복원은 INSERT OR IGNORE 방식이라 기존과 겹치는 구간은 건너뛰고,
     중복으로 망가지지 않습니다. 더 긴 히스토리를 가진 ZIP을 넣으면
     부족했던 과거 구간이 채워집니다.

Q. 적용이 잘 됐는지 어떻게 확인하나요?
   → 서버 기동 후 웹 화면을 새로고침했을 때 일봉/박스권/모니터가
     정상 표시되면 됩니다. 콘솔 로그의 복원 건수로도 확인 가능합니다.


------------------------------------------------------------
 참고 (기술 메모)
------------------------------------------------------------
- export 처리:  utils/dataset_export.py   (API: GET /api/export/dataset)
- seed 복원:    utils/dataset_seed.py     (기동 시 restore_from_seed 호출)
- 시드 위치:    data/dataset_seed.zip
- 완료 표시:    data/dataset_seed.zip.imported
- 복원 대상:    분봉 → SQLite(data/candles.db),
               일봉 → data/btc_history.json / usdt_history.json 캐시
