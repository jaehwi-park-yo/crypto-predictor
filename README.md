# 가상화폐 박스권 예측 & 그리드 매매 기획 시스템

빗썸 원화마켓(BTC_KRW)에서 **박스권 그리드 매매**를 위한 익월 박스권을
**통계 기반(1σ/2σ)**으로 예측하고, 그리드 봇 파라미터와 리워드 전망을
산출하는 멀티 에이전트 시스템.

## 에이전트 구조

```
        🎯 오케스트레이터 (전체 구조관리 · 운영지시 · 일정관리)
                          │
   ┌────────┬────────┬────┴───┬────────┬────────┐
   ▼        ▼        ▼        ▼        ▼        ▼
 ① 수집   ② 분석   ③ 예측   ④ 그리드  ⑤ 리워드  ⑥ 리스크
```

| 에이전트 | 파일 | 역할 |
|---|---|---|
| 🎯 오케스트레이터 | `main.py` | 파이프라인 지휘, 리포트 생성, 일정관리 |
| ① 데이터수집 | `agents/data_collector.py` | 빗썸/글로벌/매크로 수집 (오프라인 폴백) |
| ② 시장분석 | `agents/market_analyzer.py` | 지표 산출 + 시나리오 분류 |
| ③ 박스권예측 | `agents/box_predictor.py` | 1σ/2σ 통계 박스권 예측 (핵심) |
| ④ 그리드최적화 | `agents/grid_optimizer.py` | 간격·봇수·자본배분 (수수료 인지) |
| ⑤ 리워드계산 | `agents/reward_calculator.py` | 구간 판정·목표추천·페이스점검 |
| ⑥ 리스크모니터 | `agents/risk_monitor.py` | 이탈 판정 + 비대칭 대응 |
| ⑦ 미스터리쇼퍼 | `agents/mystery_shopper.py` | 120+ 가상 사용자 집단지성 리뷰 → 개선과제 도출 |

## 핵심 설계 원칙 (확정)

1. **자본 변수화** — 4천만원 기준, 재투자로 변동. 목표 리워드 구간은 자본의 함수로 자동 설정.
2. **빗썸 수수료 0.04%** — 왕복 0.08% > 리워드 0.008~0.02%. 리워드는 *수수료 환급* 성격이며 실제 수익은 그리드 스프레드. 그리드 간격은 수수료 인지 최소(≈0.24%) 제약.
3. **원화 보유 비중** — KRW 현금을 헷지/물타기 예비로 보유 (`KRW_HOLD_RATIO`, 기본 30%). USDT-KRW는 보류 모듈.
4. **비대칭 리스크** — 관망 기본 / 상방 이탈 관망 유지 / 하방 이탈 30% 부분손절 + 박스 재설정.
5. **통계 1σ/2σ** — 로그수익률 → 월간 √t 투영. 1σ=정상 운영범위(68.3%), 2σ=이탈 경보선(95.5%).

## 🚀 빠른 시작 (베타 사용자용)

> Python 3.10+ 필요. 포트 8000을 사용합니다.

**Windows** — `start.bat` 더블클릭

**macOS / Linux**
```bash
chmod +x start.sh   # 최초 1회
./start.sh
```

자동으로 ① 가상환경 생성 ② 의존성 설치 ③ FastAPI 서버 기동(`http://localhost:8000`)
④ 대시보드(`index.html`) 브라우저 오픈까지 수행합니다.
서버가 없어도 대시보드는 캐시/데모 데이터로 동작하며, 서버가 켜지면 60초 주기로 실시간 가격이 반영됩니다.

| API 엔드포인트 | 설명 |
|---|---|
| `GET /api/health` | 서버 상태 |
| `GET /api/price` | BTC/KRW + USDT/KRW 현재가 |
| `GET /api/history?days=90` | BTC 일봉 (캐시 우선) |
| `GET /api/predict?as_of=&capital=&krw_hold=&aggressiveness=` | 익월 박스권 예측 |

> ⚠️ 본 앱의 모든 수치는 통계적 **추정치**이며 투자 권유가 아닙니다. 투자 손실 책임은 본인에게 있습니다.

## 분봉 데이터셋 (F1 개선용)

서버(`api_server.py`) 최초 부팅 시 업비트 공개 API에서 BTC/KRW·USDT/KRW **5분봉**을 최대 약 2년치 부트스트랩합니다 (일회성, 백그라운드 5~10분 — 대시보드는 즉시 사용 가능). 이후 부팅에서는 마지막 저장 시각 이후 누락분만 증분 수집(sync)합니다.

- 저장 위치: `data/candles.db` (SQLite, WAL 모드)
- 수집 상태: 대시보드 헤더 칩 + `GET /api/minutes/status`
- 데이터 조회: `GET /api/minutes?market=KRW-BTC&unit=5&days=7`
- 수동 실행: `python -m utils.minute_data --bootstrap | --sync | --stats`
- 용도: 변동성 추정·그리드 체결률 캘리브레이션 등 예측 F1 개선

## 실행

```bash
pip install -r requirements.txt

python main.py                            # 기본 자본으로 익월 예측
python main.py --capital 60000000         # 재투자 반영 (자본 변경)
python main.py --month 2026-07            # 대상 월 지정
python main.py --aggressiveness aggressive # 공격성 다이얼 변경
```

### 공격성 다이얼 (거래량 vs 수수료 절충)

| 레벨 | 그리드 간격 | 성향 | 비고 |
|---|---|---|---|
| `conservative` | 1.0% | 수수료 절약·안정 | 봇 최소, 리워드 낮음 |
| `balanced` (기본) | 0.5% | 매매수익·리워드 균형 | **현재 채택** |
| `aggressive` | 0.3% | 거래량/리워드 극대화 | 봇·수수료·슬리피지↑ |

> 왕복 수수료 0.08%가 리워드 상한 0.02%보다 크므로, 그리드 간격은 항상
> 수수료 인지 최소(≈0.24%) 이상으로 강제됩니다.

> 네트워크가 없으면 합성 데이터로 폴백해 파이프라인이 그대로 동작합니다.
> 리포트는 `reports/{YYYY-MM}_report.txt`에 저장됩니다.

## GUI 대시보드 (Streamlit)

```bash
pip install -r requirements.txt
streamlit run gui/app.py
```

- **시점 고정(as-of) 예측**: 기본값은 *2026-04-30까지 데이터로 2026-05 박스권 예측*.
  사이드바에서 기준 시점을 바꾸면 그 시점까지의 데이터만으로 다음 달을 재예측합니다.
- **실시간 조정 항목**: 예측 기준 시점 · 자본 · KRW 현금비중(30%+) · σ레벨(자동/1σ/2σ) · 그리드 공격성.
- **차트**: 캔들 + 1σ/2σ 박스밴드 음영 + 권장 박스 + 그리드 라인 오버레이.
- **하단 패널**: 그리드 봇 설정 · 리워드 목표 구간 · 복합전략(BTC+USDT) 월수익률.

> 복합전략의 BTC 레그 수익은 휴리스틱이 아니라 **검증된 백테스트의 월평균**을 사용합니다.
> (기준 시점 이전 구간만 사용 → 미래 정보 누설 방지)

### 예측기 작동 프로세스

```
  [as-of 시점] ─► history 슬라이스(≤as_of) ─► 최근 31일 σ 추정
       │                                          │
       ▼                                          ▼
  익월 라벨 산출                       1σ/2σ 밴드 √t 투영(drift=0)
       │                                          │
       └────────────► σ레벨 선택(자동/수동) ──────┘
                            │
                            ▼
            GridOptimizer ─► 리워드 목표 ─► (옵션)복합전략
                            │
                            ▼
                   PredictionSnapshot ─► Streamlit 차트/지표
```

핵심 백엔드는 `services/prediction_service.py`의 `predict_as_of()`로,
실시간 수집기에 의존하지 않는 **결정론적·재현 가능한** 예측을 제공합니다.

## 백테스팅

```bash
python backtest.py                              # 일봉 기준 (보수적 하한)
python backtest.py --granularity intraday --steps 96   # 분 경로 합성(미세진동)
python backtest.py --sweep                      # 반응빈도 × 공격성 민감도 매트릭스
python backtest.py --save                       # CSV + 요약 저장
```

- **분해능(`--granularity`)**: `daily`(일봉 휴리스틱, 하한선) / `intraday`(일봉→분 경로 합성).
- **`--sweep`**: 봇 반응빈도(행) × 공격성(열) CAGR 매트릭스. 분해능 의존성을 명시.

> ⚠️ 그리드 수익은 봇의 실제 반응빈도(분/틱)에 좌우됩니다. 합성 브라운 경로의
> 교차횟수는 분해능에 따라 √n 으로 증가하므로 **절대 수치는 참고용**이며,
> 실채택 전 빗썸 분봉 데이터로 재보정이 필요합니다. 일봉 결과가 보수적 하한선입니다.
>
> **핵심 발견**: 모든 반응빈도에서 넓은 간격(conservative)이 좁은 간격(aggressive)보다
> 순수익이 높음 — 좁은 간격은 동일 수수료로 더 작은 스프레드를 잘게 나눠 손해.
> 좁은 간격은 '리워드용 거래량 확보'에만 의미가 있으나, 리워드(≤0.02%)가
> 추가 수수료(0.04%/체결)를 못 덮으므로 순효과는 마이너스.

## 주의

- 거래량/리워드 추정치는 **명시적 가정 기반 휴리스틱**이며 실거래 데이터로 보정해야 합니다 (`config.py`의 `GRID_FILL_EFFICIENCY` 등).
- 본 시스템은 **기획/예측·파라미터 산출용**이며 실제 주문 실행(비공개 API) 기능은 포함하지 않습니다.
